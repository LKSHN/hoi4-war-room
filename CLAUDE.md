# HOI4 Tool

A second-monitor companion for Hearts of Iron IV. You follow a guide step by step while playing, tick off what's done, and check focus/research orders, division templates and production numbers without leaving the game.

It started as a single-page checklist built from MachiavellianStrategist's "Ultimate Germany Guide" (https://www.youtube.com/watch?v=s0zNamkHkG0): Allies down by May 1940, then USA, then Barbarossa by Aug 1941.

## Current state

`index.html` is the page: markup and the `#ic-*` SVG icon sprite. Styles are in `css/` (one file per tab plus `base.css`, `edit.css`, `tooltip.css`, linked in cascade order) and the app is in `js/` (one file per tab plus `core.js`, `lists.js`, `ui.js`, `edit.js`, and `main.js`, which loads the guide and starts everything and must stay last). The JS files are plain `<script>` tags sharing one global scope, not modules, so `file://` keeps working; a file may only use, at load time, what earlier files define (inside functions anything goes). Guide content lives in `guides/`, and cropped game screenshots are in `img/`. No build step and no dependencies. Open the file in a browser and it works. The fonts come from Google Fonts. Code is formatted conventionally (2-space indent, one statement per line); keep new code that way.

Three tabs:
- **Game plan**: about 90 steps grouped into phases. Each phase links to its video timestamp. The next unticked step is highlighted, and some steps have a "▸ Show screen" reveal with a screenshot.
- **Focus & research**: national focus order and research order, side by side.
- **Builds & numbers**: reference cards (division template with numbered pins, tank/plane designs, Alkett MIO trait order, doctrines, build queues, production numbers, advisor order). Screenshots open in a lightbox.

Where things are:
- `guides/index.js` lists the guides for the picker (`GUIDES`). Each guide is a `.js` file that calls `registerGuide({...})` with JSON-shaped data. It's loaded with a `<script>` tag, not `fetch`, so `file://` keeps working. The format is documented at the top of `guides/germany-blitzkrieg.js`.
- A guide has `meta`, `images`, `plan`/`focus`/`research` (groups of steps with stable `id`s, plus optional `n`, `tag`, `img` and `date`), `chapters`, `builds` (sections of `fig`/`card` items, text allows `**bold**`) and `legacy`.
- Step IDs are permanent. Rewording a step keeps its ID, and a new step gets a new ID. Never reuse one.
- In `js/lists.js`: `build()` renders a list, `refresh()` updates counts, progress bar and the "next" highlight, and `buildBuilds()` (`js/builds.js`) renders the Builds tab from data. Pick a guide with `?guide=<id>`.
- Date tracker: plan groups carry `by` (done-by date) and `approx`. `applyDates()` marks steps `behind` (unticked and past `by`) and `later` (phase not started), and tags each phase as past/now/later. Focus and research have no dates yet.
- Glossary: `guides/glossary.js` (`GLOSSARY`) holds shared game terms, and `guide.glossary` adds guide-specific ones (same `id` overrides). `glossify()` wraps matching phrases in rendered text in `.gl` spans, and one shared `#tip` element shows the definition on hover, focus or tap. Clicking a term doesn't tick its step. In definitions, `**x**` is gold, `{+x}` green, `{-x}` red, and `patch: true` adds a "may differ between patches" line.
- Focus tree: `guides/trees/germany-1.19.1.js` (`registerTree`) holds the full German tree as facts only (names, x/y grid positions, days, prerequisites, mutually exclusive, bypass), extracted from the user's 1.19.1 game files with all DLC and default rules. The guide points at it with `meta.focusTree`, and each focus step links to a game id with `"focus"`. `projectFocuses()` chains the guide's focuses back to back from 1 Jan 1936 for projected dates (also used by the date tracker on the focus list). `buildTree()`/`updateTree()` draw the "Focus tree" tab, where clicking a numbered guide focus ticks it. No game textures or icons: each focus has an `ic` theme (tank, plane, ship, flag, rings, swords, eagle... 22 in all) picked by `ICON_RULES` in the extractor from the *name* of its in-game icon, drawn with our own SVG symbols (`#ic-*` sprite at the top of `index.html`). `computeExcluded()` marks what the guide's choices rule out (`EX`): focuses mutually exclusive with a guide focus, then anything only reachable through those. They show struck through in red, and the "Complete tree" toggle (`prefs.treeHideEx`) hides them.
- Focus effects: each focus has `fx`, short lines summarising its `completion_reward` in our own words (political power, XP, factories, research bonuses, spirits with their modifiers, annexations, war goals, claims and cores, opinion changes, guarantees, factions, pacts). Opinion values come from `common/opinion_modifiers`, tag aliases like `SOU` from `common/country_tag_aliases`, and country names use their 1936 ruling party (SOV is "Soviet Union"). AI strategy changes are hidden in game and skipped. Events sent to another country are followed into `events/*.txt`: each answer is summarised (ROOT/FROM swapped, effects on them written as "they …") and labelled "if they accept/refuse" from what it does; skipped when the game's own tooltip already spells out "Effects if they accept/refuse". `tools/focus-tree/effects.py` makes them, evaluating conditions as for Germany at peace with all DLC and taking the first matching branch. Scripted effects are skipped (32 focuses show "no direct effect listed"). In-game flavour descriptions are deliberately not copied. Shown in the tree tooltip and when hovering a focus's "days · done ≈" line in the focus list.
- Conditions: `tools/focus-tree/triggers.py` turns trigger blocks into short English ("we have at least 725,000 men in the army", "Czechoslovak Republic has completed A German Satellite or A German Protectorate"). Used for each focus's `req` (from `available`) and `byp` (from `bypass`), for the AI odds on other countries' event answers ("AI: never if … ; less likely if …", from `ai_chance`), and for branching effects: the peacetime branch is shown as before, other branches get "Instead, if <condition>: …" lines. Flags, variables and DLC checks are left out rather than guessed, and "if the owner of X isn't us yet" guards are skipped as bookkeeping.
- Research tree: `guides/trees/research-1.19.1.js` (`registerResearch`) holds 328 techs in the 9 folders that exist with every DLC (doctrines have their own system since 1.17), with names (techs without their own name use the equipment or module they unlock, as in game), screen positions, year labels and section titles from `interface/countrytechtreeview.gui`, cost, links, exclusives, our icon theme and effects, plus Germany's 53 start techs. Layout rule: each line of techs has a gridbox (`<tech>_tree`, else inherited from the parent); `LEFT` gridboxes run years across (tech y → screen x), `UP`/`UPPER_LEFT` run years down. The guide points at it with `meta.researchTree`; research steps link with `"tech"` (or `"project"` for special projects, which aren't techs). `prepResearch()`/`buildResearch()`/`renderFolder()`/`updateResearch()` draw the "Research tree" tab: folder buttons with guide progress, cards sized to their neighbours, green = researched (start or ticked), gold = next guide tech, clicking a numbered tech ticks it. The view drags with the mouse (touch keeps native scrolling; a drag never ticks) and zooms like the focus tree: the wheel zooms around the pointer, −/+/Fit buttons in the bar. `zoomRes()` scales `#resCanvas` with a transform and sizes `#resSizer` to the scaled size so the scrollbars match; the level is kept in `prefs.resZoom`. `goNextTech()` ("Go to next tech", and the first time the tab opens) switches to the next guide tech's folder and centres it; that folder's button gets a gold dot (`.hasnext`). Edit mode picks research by tech name (`edTechList`).
- Designs: `guides/trees/designers-1.19.1.js` (`registerDesigners`) holds the tank, plane and ship designers: frames (chassis, airframes; base stats resolved through archetype and parents, per-frame slots and count limits, upgrades), role archetypes (`duplicate_archetypes`, e.g. `medium_tank_artillery_chassis` with hardness 0.65), modules (category, add/multiply stats, `allow`/`forbid` roles, `slotcats` a module opens in other slots, like a medium turret letting the main armament take medium guns), upgrades (per-level add and multiply), and `usedBy` (battalions that need each role, from `common/units`). Stats: `(base + module adds + upgrade adds × level) × (1 + multipliers)`, checked against the guide's screenshots: every stat research and MIO don't touch matches exactly (SPG1 cost 15.2, fuel 2.35, defense 2.8; F2 thrust 25, weight 25, range 910). Research and MIO bonuses aren't included and the UI says so. The guide's `designs` (SPG1, Flammpanzer III, F2, C2; modules worked out from the screenshots and the stats) render in the "Designs" tab (`renderDesigns()`/`renderDesigner()`), with the in-game value (`seen`) under each stat, warnings (empty required slots, count limits, role/module mismatches, weight above thrust) and who uses it. In edit mode every control is live, and designs can be added or deleted. Ships: frames are the designer hulls (`ship_hull_*`; the premade `destroyer_1` etc. of the old naval system are skipped), the design's `role` is the hull archetype, and `shipClass()` works out the class from `shipUnits` (light vs heavy cruiser from a module's `addtype` such as `capital_ship` on medium guns, battleship vs battlecruiser from the armor module). Modules also carry `forbidcats` (medium guns rule out light guns, warned about), and `add_average_stats` (piercing) are averaged over the modules that have them. The guide's ships are Type II, Zerstörer 1934 and Admiral Hipper as in Germany's 1936 history file, plus the Hipper light cruiser refit, whose modules the video doesn't show (a guess, and the note says so). Ship stats aren't checked against an in-game screen yet, and the page says so.
- Regenerating the designers: `extract_equipment.py <game dir> guides/trees/designers-<patch>.js <patch>`.
- Production: `guides/trees/equipment-1.19.1.js` (`registerEquipment`) holds land and air equipment a line can build (name, Germany's own name from `GER_<id>` localisation, archetype, year, cost in IC, category); ships are left out. The guide's `production.states` are snapshots tied to a plan `step` (`title`, `mils`, `img`, `ts`, `n`), each with `lines` in priority order (`name`, `eq` or `design`, `kind`, `f` factories, `cap` limit, `rest` for the line that takes what's left, `n`). A line keeps its `id` between states, so `pDiff()` can tell added, removed, re-designed (Bf 109 D → F1ca), factory changes and priority moves (lines outside the longest common order). The "Production" tab (`renderProduction()`/`prodPanel()`) shows a timeline of states (✓ when the step is ticked, the next one selected by default), the list of changes, then the state before and the selected state side by side. Edit mode edits the selected state: title, step, factory total, note, and each line's design or equipment, factories, limit, rest, priority; states can be added (a copy) or deleted. The Day one and Todt states match the screenshots; later ones apply the guide's spoken changes to the previous state, and the page says unmentioned lines are assumed unchanged. Regenerate with `extract_production.py <game dir> guides/trees/equipment-<patch>.js <patch>`.
- Construction: `guides/trees/construction-1.19.1.js` (`registerConstruction`) holds the buildings (name, construction points per level, `extra` per level, max level, `slots` if it shares state slots, `prov` if provincial) and all 1,081 states (name, 1936 `owner`, base `slots` from the state category, `b` buildings on 1 Jan 1936). Base slots aren't checked against queues: Germany clearly gets bonus slots (the 1936 queue puts 9 factories in Westfalen's 8). The guide's `construction.lists` are queues tied to a plan `step` (`title`, `civs`, `uses` such as consumer goods and trade, `img`, `ts`, `n`, `items` of `{state, b, n}` in queue order). The "Construction" tab (`renderConstruction()`, `consQueue()`, `consSide()`) has a timeline like Production, the queue drawn like the game's, and a side panel with totals and costs per building and each state's 1936 buildings. `consAlloc()` gives each item up to 15 civilian factories in order from what `uses` leaves; this matches both screenshots (15/15 then 5/15 in 1936; 15, 15, 4 in 1937). Edit mode edits everything (state picker with the German 1936 states first). Regenerate with `extract_construction.py <game dir> guides/trees/construction-<patch>.js <patch>`.
- MIOs: `guides/trees/mio-1.19.1.js` (`registerMIO`) holds Germany's 25 military industrial organisations (only the `GER_` file: generic ones name Germany just to exclude it). Generic templates (`include`) are resolved with the country's `trait`, `add_trait`, `override_trait` (fields replace) and `remove_trait`; traits shown only without a DLC are dropped. Each trait has its absolute grid `x`/`y` (`position` plus its `relative_position_id`'s, `@variables` resolved), `all`/`any`/`need` parents, `ex` exclusives, `for` equipment, `fx` bonuses (equipment bonuses as %, production and organisation modifiers via `Summariser.modifier`) and an `ic` theme from its icon name. The Alkett tree matches the screenshot cell for cell. The guide's `mios` entries (`org`, `step`, `order` of trait ids, `designs` it's assigned to, `img`, `ts`, `n`) number the queue on the tree. The "MIOs" tab (`renderMIO()`, `renderMioInfo()`, `renderMioTree()`) has the guide's MIOs as buttons plus a list of all 25 by kind, an info column like the game's (equipment, initial trait, guide step, assigned designs, numbered queue, hovered trait details) and the tree (SVG elbows, dotted for any-parent, red mark between exclusives, struck-through traits ruled out by the queue). `mioIssues()` warns when the queue takes a trait before its parents or takes two exclusives. Edit mode: click traits to queue or unqueue them, reorder, set step, designs and note, add any MIO to the guide. Regenerate with `extract_mio.py <game dir> guides/trees/mio-<patch>.js <patch>`.
- Special projects: `guides/trees/projects-1.19.1.js` (`registerProjects`) holds the 49 projects Germany can run (`allowed` checked for tag, every DLC owned): name, specialization, first project tag, `parents`, `needs` (the `available` block with `FROM` unwrapped, phrased by `triggers.py`), breakthrough `cost` per specialization, `time` (days per prototype) and `complexity` (min–max progress per prototype) from `script_constants`, `res`, and `out` (modules, equipment, battalions, techs from `SP_UNLOCK_TECH` tooltips, design cost bonuses, other effects via `Summariser`). Prototype rewards aren't listed and the page says so. The guide's `projects` are its picks in order (`project`, `step` it's tied to, usually its research entry, `n`); a pick is done when that step is ticked. The "Special projects" tab (`renderProjects()`, `projectCard()`) shows the picks on top (click to jump to the card) and one column per specialization, grouped by tag with parents first, picks numbered in gold and done ones green. Edit mode: ★ on a card recommends it; picks can be reordered, tied to a research or plan step, noted or removed. Regenerate with `extract_projects.py <game dir> guides/trees/projects-<patch>.js <patch>`.
- Divisions: `guides/trees/units-1.19.1.js` (`registerUnits`) holds land battalions and support companies from `common/units` (name, abbreviation, group, width, HP, organisation, manpower, training time, supply, suppression, weight, recon, entrenchment, equipment needs) plus equipment archetype names. The guide's `divisions` has `templates` (`support` list and `combat` columns, `seen` in-game stats, `img`, `ts`) and `training` rows (plan `step`, `template`, `count`, optional `n`). The "Divisions" tab has two sub-tabs (`prefs.divSub`): the training plan (`renderTraining()`, dated from each step's phase, done when the step is ticked, running totals and manpower/equipment needs) and the division designer (`renderTemplates()`/`renderTemplate()`: 5 support slots and a 5×5 combat grid). `tplStats()` sums width, HP, manpower, weight, suppression, recon and entrenchment (exact against the MARK screenshot), takes the max training time, and averages organisation; supply leaves out research, so it's marked ≈, and attack/defense/speed only show the in-game values. Equipment names add the guide design that fills that role. Only MARK's battalions are known from the video; the others are empty with a note. Regenerate with `extract_units.py <game dir> guides/trees/units-<patch>.js <patch>`.
- Regenerating the research tree: `extract_research.py <game dir> "<game>/history/countries/GER - Germany.txt" <out.json>`, then `map_research.py <out.json> guides/germany-blitzkrieg.js` (dry run; `--write` to link the guide; "UP" = next unowned tech in that line, with hand-checked `OVERRIDES` and `PROJECTS`), then `emit_research.py <out.json> guides/trees/research-<patch>.js <patch>`. Both extractors share `gamedata.py` (localisation and name cleaning).
- Regenerating the tree for a new patch: `tools/focus-tree/` (Python, dev only, not a build step). Run `extract_tree.py <game dir> <germany.txt> <out.json>`, then `emit.py <out.json> guides/trees/germany-<patch>.js guides/germany-blitzkrieg.js <patch>`, then `validate.py` to check the guide order against prerequisites. Point `meta.focusTree` at the new file.
- Editing: "Edit guide" (`enterEdit()`) swaps the plan/focus/research lists for edit rows (`editList()`) and makes Builds text editable in place (`editBuilds()`, via the `_bind` that `bindEl()` puts on rendered elements; `**bold**` is kept). Edits are a full copy of the `EDITABLE` sections (`plan`, `focus`, `research`, `builds`) saved in `hoi4-tool-edits:<guideId>` with a `base` hash of the original, applied by `applyEdits()` before anything renders; if the original guide file changes later, a notice says so. Done saves and reloads so the tree, dates and counts use the edits. New steps and phases get `u-` ids. Export as JSON or as a `.js` guide file (a new guide once its `meta.id` changes and it's listed in `guides/index.js`), import either back, or reset to original. Future views (research tree, designers, production, construction, MIOs) should edit their data the same way: add the section to `EDITABLE` and write into `G`.
- Menu: the items in `nav.tabs` are links to `#<tab>` (styled like the old buttons), so a menu opens in a new browser tab with middle click or Ctrl+click. `showTab(name, push)` in `js/ui.js` keeps the address in step (a click pushes a history entry, so Back returns to the previous menu; loading only corrects it), and the page opens on the `#tab` in the address, else the last one used. Several browser tabs stay in sync: a `storage` listener takes ticks and the game date saved by another tab, so a stale tab never saves its old copy over them. Edit mode isn't synced between tabs.
- State: `hoi4-tool:<guideId>` holds `{ticks, open, date}` per guide, and `hoi4-tool-prefs` holds `{guide, tab, hide}`. On first load, `guide.legacy` maps the old positional keys (`hoi4-ger-checklist-v1`, `g12`/`f3`/`r40`) to stable IDs. The old keys are left in place.
- `.claude/launch.json` serves the folder on port 8765 (`python -m http.server`) for previewing.

Known weak spots:
- Progress is per browser and doesn't follow the user between PCs.
- The game patch for the Germany guide isn't recorded (`meta.patch: null`), and the UI says so.
- Most Germany phase dates are estimates (`approx: true`, shown with ≈). Only a few are anchored by the guide (see `meta.datesNote`).
- The focus tree is from patch 1.19.1, likely newer than the video. Five guide focuses have prerequisites the guide never takes (Sea Lion, Tannenbaum, Reintegrate Luxemburg, Loyalty to the Führer, Autarky Achieved); the tree assumes they were bypassed and says so in the tooltip.

## Conventions

- Conventional Commits (`feat:`, `fix:`, `refactor:`, `chore:`, `docs:`, `style:`). When asking the user to commit and push, always give them the commit message.
- The user merges and pushes each finished branch themselves. Before committing, check the branch and start a new one from `master` if needed.
- Never add Claude as author or co-author: no `Co-Authored-By` trailers, no "Generated with Claude" lines in commits or PRs.
- Prefer targeted, scoped edits over rewrites. Don't over-deliver beyond the step being worked on.
- Keep it working without a build step unless there's a clear reason to add one, and discuss that first.
- Cache busting: GitHub Pages lets browsers cache files for 10 minutes, so a new page can run with old scripts or data. Whenever anything in `css/`, `js/` or `guides/` changes, run `python tools/bump_build.py`: it sets a new `BUILD` in `js/core.js` and the matching `?v=` on every `<link>`/`<script>` in `index.html` (they must all match).
- Generated data files (`guides/trees/*.js`) are written by `write_register()` in `tools/focus-tree/gamedata.py`: one entry per line, longer values split over lines, so they stay readable and diffable. New extractors use it too, with deterministic (sorted) ordering so a rerun gives the same file.
- The user plays on Windows and uses the tool on a second monitor, so test at roughly 1280–1920 px wide as well as narrow widths.
- Game facts drift with patches. When a number or mechanic is uncertain or from an older source, say so in the UI rather than presenting it as fact.
